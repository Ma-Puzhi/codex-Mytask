# My Tasks 2.3.2 后续维护要求

在已有 My Tasks 上原地更新，保留原界面、原项目、私人访问权限和全部历史数据。

## 任务讨论

- 点击任务或“和 GPT 讨论该任务”显示聊天 / Work 选择；`•••` 打开详情。
- 新标签页打开任务专属会话；没有绑定时新建，有绑定时进入同一会话。
- 同一任务的聊天与 Work 分别保存，任务之间也互不覆盖。
- 会话出现真实持久地址后，由启动页调用 `set_task_ai_workspace` 保存到 D1。
- 会话确认打开且绑定已保存后，自动关闭本次启动的中间页，保留 My Tasks 主页面和原生会话；保存失败时保留启动页重试。
- 明确删除后重建；登录、网络、含糊加载错误不当作删除。保留用户主动重新建立选项。
- 使用 `companion/` 的浏览器扩展及公开网页入口，不调用 OpenAI API、私有 ChatGPT API，不将当前任务控制台替换成聊天。
- 扩展未安装时提示一次安装步骤，并提供手动打开和绑定。
- 网页自动化的验证范围必须诚实说明，不能以单元测试代替真实账号端到端验证。

## 仓库链接

- 只保留一个仓库链接输入框、保存链接和打开仓库按钮。
- ChatGPT 可以通过 `set_task_repository_link(id,url)` 将用户提供的仓库链接保存到对应任务。
- GitHub、GitLab、Gitee 及其他 HTTPS 仓库网页均可保存；拒绝非 HTTPS、带账号密码及仅首页的网址。
- 点击在新标签页打开仓库，保持 My Tasks 页面；不要求浏览器辅助扩展或本机访问。
- 不显示或发起创建仓库、上传、提交、推送、拉取、分支、差异、本机路径和 Private / Public 配置流程。
- 保留历史数据及原有仓库链接。不要因为未来维护恢复已移除的 Git 操作。

## 数据与兼容

- `task_ai_sessions` 使用 `(task_id, mode)` 主键，保留旧工作区及聊天记录兼容读取。
- 使用 `drizzle/` 增量迁移，禁止清空用户数据。
- 保留长期任务、每日计划和记录、原文复盘、休息日、任务历史及历史仓库数据。
- 保留插件全局 / 会话入口，所有读写按用户隔离。
