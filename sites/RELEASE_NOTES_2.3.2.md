# My Tasks V2.3.2 使用说明

原来的 [My Tasks](https://mytask.example) 已原地更新。现有任务、复盘、计划、仓库链接及会话绑定保留，不需要重新创建网站。

## 本次修复

同一个任务的同一种模式始终使用同一个已绑定会话地址。

- 关闭聊天 / Work 标签页后，再次选择会重新打开原来的对话。
- 中间跳转页是否关闭，不影响绑定。提前关闭中间页后，扩展仍记录新会话地址，下次启动会补写绑定。
- 首条任务消息发送后页面重新加载，也能识别已发送消息并保存会话地址，不重复发送。
- 已打开的任务会话可以直接切回该标签页；已关闭时打开同一个地址。
- 只有明确确认原会话已删除或不存在，才重新创建并绑定新会话。登录和网络错误不会被当作删除。
- 确认会话打开且绑定已保存后，仍自动关闭中间页，保留 My Tasks 主页面和会话页。

聊天与 Work 各自绑定：同一任务的聊天入口始终进入它的聊天，Work 入口始终进入它的 Work。

## 三个文件

| 文件 | 用途 |
| --- | --- |
| `My_Tasks_V2.3.2.zip` | 完整项目源码，供备份及后续原地更新 |
| `My_Tasks_V2.3.2_使用说明.md` | 本说明 |
| `MyTasks_Chat_Bridge_V2.3.2.zip` | Chrome / Edge 浏览器辅助插件，含自动打开、绑定和关闭中间页逻辑 |

浏览器插件与 ChatGPT 中的 My Tasks 插件是两个入口：前者负责浏览器里的任务会话；后者继续使用原有的 My Tasks，不需要另建一个插件。

## 更新已经安装的浏览器插件

1. 解压 `MyTasks_Chat_Bridge_V2.3.2.zip`，里面的 `MyTasks_Chat_Bridge` 文件夹包含 `manifest.json`。
2. 将这个文件夹里的文件复制到原来加载扩展的文件夹，替换旧版本文件。
3. 打开 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions`，找到 **My Tasks · Chat / Work Bridge**，点击重新加载按钮。
4. 刷新 My Tasks，然后点击聊天或 Work。扩展管理页应显示版本 **2.3.2**。

优先替换原扩展文件并重新加载，以保留尚未写入服务器的本地绑定。只有原来的扩展文件夹已经丢失时，再移除旧扩展、加载这次解压出的文件夹。不要同时启用两份相同扩展。

如果此前的对话从未成功绑定，本次更新无法凭空找回它：打开仍保留的原对话，复制地址，通过启动页的“暂时手动打开并绑定”保存一次即可。

## 第一次安装浏览器插件

1. 解压浏览器插件 ZIP。
2. 打开浏览器的扩展管理页，开启开发者模式。
3. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的 `MyTasks_Chat_Bridge` 文件夹。
4. 保持 ChatGPT 登录，回到 My Tasks 选择聊天或 Work。

## 仓库链接

任务详情只保留仓库链接、保存链接和打开仓库。也可以将仓库链接发给 ChatGPT，让它保存到对应任务。仓库入口不需要浏览器辅助插件、本机 Git 或本地文件访问。

## 项目源码的用途

解压完整项目 ZIP 可以查看代码、数据库增量迁移和测试。用 Sites 更新时，要求依据 `sites/SITE_BUILD_PROMPT.md` 原地更新已有 My Tasks，复用 `.openai/hosting.json` 的项目身份和私人访问权限，不创建第二个网站、不清空 D1 数据。

## 验证范围

模拟浏览器 API 的回归检查涵盖：会话页关闭后复用原地址、中间页提前关闭、扩展临时状态重置、聊天 / Work 独立绑定、已删除会话重建、首条消息后的整页加载及不重复发送任务上下文。原有任务数据、权限隔离、中间页自动关闭、TypeScript、相关 ESLint 和生产构建检查通过。

这些检查没有在你的本机真实账号中远程实测。浏览器修复需要加载或重新加载 **2.3.2** 扩展后生效。
